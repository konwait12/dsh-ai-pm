# 人类审查清单 · 问题清单（Issue Record · 跨阶段共享）

> 本清单给 **业务方 / 决策 Owner / PM** 在审查 `issue-record.md` 时使用——你要确认"还有什么没解决"是真的、归对了人、有期限。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每个问题的类别对吗？BLK（真阻断）/ RSK（风险）/ DEC（等决策）/ INF（缺信息）/ CLS（歧义）/ OUT（范围外）？
- [ ] 有没有被 AI 错归类的问题？（比如把 DEC 写成 INF，把 RSK 写成 BLK）
- [ ] 问题描述里的来源（SRC-* / 上游产物）是否与你看到的一致？

## 完整性
- [ ] 之前各阶段讨论过的"待确认/冲突/风险"，是不是都进到这份清单了？有没有漏的？
- [ ] 有没有你明确提过、但清单里找不到的问题？
- [ ] 有没有 AI 自己发明的、你从没说过的问题？（这类要删除）

## 责任与期限
- [ ] 每个 open 问题是否都有 owner？有没有写着"待定"的？
- [ ] 每个 BLK / DEC 是否有目标关闭日期？
- [ ] 有没有超过 30 天还 open、且没有升级记录的问题？

## 风险接受
- [ ] 标记为 `accepted`（接受风险不再行动）的问题，是不是你本人/决策者明确接受的？有没有 AI 替你接受的？
- [ ] 每个 `accepted` 是否都记录了接受条件与日期？
- [ ] `resolved` 的问题是否都链接到了关闭它的产物变更？有没有"嘴上说解决"的？

## 与 PRD 确认的关系
- [ ] 在 PRD 确认前，这些 open 问题是否要么解决、要么被显式接受为风险？
- [ ] 这份清单能否作为"还有什么没解决"的权威答复拿给业务方/技术方开会？

## 最终判断
1. **这份问题清单完整且归对了吗？** 是，可以直接推进；否，缺哪几项 / 哪几项归错了？
2. **确认前要清零哪些问题？** 请圈定 BLK / DEC 的处理顺序与负责人。
