# NFR 目录 · 非功能性需求分类

> 借鉴 Volere Requirements Specification Template §10-17 八类 NFR。
> 每个 NFR 类别包含：定义、触发条件（何时必须填写）、典型验收标准模板、示例。
>
> 注：本文示例已统一使用通用业务场景（内容平台、企业服务、电商等），避免与 `test/skills/` 下的测试夹具业务域（招聘网站、设备预测性维护、客户邀约活动等）同域，防止误导。

---

## NFR-10: Look & Feel（外观与感受）

**定义**：产品的外观、品牌一致性、视觉体验相关要求。

**触发条件**：
- 有品牌规范（logo/配色/字体）需要遵循
- 面向 C 端用户且有视觉体验要求
- 多语言/多地区需要适配

**验收标准模板**：
```
Given 用户访问{页面}, when {操作}, then 产品的外观应符合{品牌/视觉规范}的{具体要求}
```

**示例**：
- "内容详情页必须自动应用品牌视觉规范（logo/配色/字体），保持所有对外页面视觉一致性"
- "投递表单在移动端和桌面端均可完整使用（响应式设计）"

---

## NFR-11: Usability（易用性）

**定义**：产品的易学性、效率、错误率、用户满意度相关要求。

**触发条件**：
- 有明确的目标用户群体且其技能水平已知
- 有竞品或行业可用性基线
- 有用户测试计划

**验收标准模板**：
```
Given 用户群体为{角色}, when 执行{任务}, then {效率指标}应达到{量化目标}
```

**示例**：
- "内容编辑完成一次内容发布的平均操作步骤 ≤ 5 步"
- "读者从进入列表页到完成阅读的时间 ≤ 3 分钟"
- "新内容编辑无需培训即可完成基本内容发布（首次成功率 ≥ 80%）"

---

## NFR-12: Performance（性能）

**定义**：响应时间、吞吐量、并发能力、资源消耗相关要求。

**触发条件**：
- 有明确的用户量/并发量预期
- 涉及大文件上传/下载
- 有实时性要求的场景（如预警推送）

**验收标准模板**：
```
Given {负载条件}, when {操作}, then 系统应在{时间阈值}内完成{响应动作}
```

**示例**：
- "内容列表页首屏加载时间 ≤ 2 秒（P95，4G 网络）"
- "图片上传（≤ 5MB）完成后 ≤ 3 秒内显示预览"
- "支持 100 个内容编辑同时使用后台编辑功能，无降级"
- "实时监控平台从数据异常到预警推送延迟 ≤ 30 秒"

---

## NFR-13: Operational（运维）

**定义**：部署、监控、备份、恢复、日志、迁移相关要求。

**触发条件**：
- 有本地化部署需求（数据不出厂区）
- 有运维团队需要监控告警
- 有数据备份与恢复要求

**验收标准模板**：
```
Given {运维场景}, when {操作/事件}, then 系统应{运维行为}
```

**示例**：
- "平台必须支持本地化部署（数据不出厂区），满足甲方审厂要求"
- "系统故障后应在 4 小时内恢复服务（RTO ≤ 4h），数据丢失 ≤ 1 小时（RPO ≤ 1h）"
- "管理员可查看数据采集状态（在线/离线/异常），异常时自动告警"

---

## NFR-14: Maintainability（可维护性）

**定义**：代码质量、模块化、测试覆盖、文档、可扩展性相关要求。

**触发条件**：
- 预期有持续迭代（多期规划）
- 涉及外部供应商/外包开发
- 需要交接给其他团队

**验收标准模板**：
```
Given {维护场景}, when {操作}, then 系统应支持{可维护性要求}
```

**示例**：
- "核心业务规则（BR-XXX）必须可配置而非硬编码，配置变更无需重新部署"
- "API 契约必须有 OpenAPI 文档，供下游消费方对接"

---

## NFR-15: Security（安全）

**定义**：认证、授权、数据保护、审计、漏洞管理相关要求。

**触发条件**：
- 涉及个人信息（PII）或敏感数据
- 有合规要求（GDPR/个人信息保护法/等保）
- 涉及支付或金融数据
- 有外部用户访问

**验收标准模板**：
```
Given {安全场景}, when {操作}, then 系统应满足{安全要求}
```

**示例**：
- "用户内容数据存储需遵循适用法规要求，数据保留期不超过 24 个月"
- "所有 API 调用必须通过 HTTPS，敏感字段（密码/身份证号）传输加密"
- "内容编辑只能查看自己发布的内容，不可跨账号访问"

---

## NFR-16: Cultural/Political（文化与政策）

**定义**：多语言、多地区、法务合规、组织政策相关要求。

**触发条件**：
- 跨国家/地区使用
- 有特殊行业法规
- 有内部合规政策

**验收标准模板**：
```
Given {文化/政策场景}, when {操作}, then 系统应满足{政策要求}
```

**示例**：
- "多语言版本需按业务方规划分阶段提供（具体语言清单与排期待业务方确认）"
- "用户数据存储必须在指定地区服务器"

---

## NFR-17: Legal（法律）

**定义**：许可证、知识产权、合同义务、审计相关要求。

**触发条件**：
- 采购第三方组件/平台
- 有知识产权归属要求
- 需通过外部审计

**验收标准模板**：
```
Given {法律场景}, when {操作}, then 系统应满足{法律要求}
```

**示例**：
- "第三方供应商合同需包含知识产权归属条款（平台定制部分归甲方）"
- "AI 能力供应商须提供模型训练数据来源合规声明"

## 使用指南

1. **不是所有类别都必须填**：只填写本需求触发的 NFR 类别。触发了但空着 = 标注"本需求不适用 NFR-XX，理由：..."
2. **NFR 与 AC 的关系**：NFR 可以体现在对应 FUN 的验收标准（AC-XXX）中。例如 NFR-12 性能要求的 AC："Given 100 并发用户，when 同时查询列表，then 响应时间 P95 ≤ 2 秒"
3. **NFR 与 BR 的关系**：NFR 也可以体现在业务规则（BR-XXX）中。例如 NFR-15 安全要求的 BR："用户内容在发布后 24 个月自动归档（不可检索），25 个月时物理删除"
4. **参考**：`02-共享机制与产物契约.md` `function-description` DoD D4.8
