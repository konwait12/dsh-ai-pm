# 人类审查清单 · 业务规则（business-rules）

> 本清单给 **PM/业务方** 在审查 AI 产出的 §业务规则（BR-XXX）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每条 BR 是否与业务方确认过的口径一致？阈值、配额、折扣、截止时间等数字有没有被 AI 改过或猜过？
- [ ] 计算类规则（折扣、配额、得分、期限）的公式、单位、舍入规则是否与业务方理解一致？
- [ ] 规则所引用的 `ST-XXX` / `FEA-XXX` 是否确实存在，且确实是该规则的来源？

## 完整性
- [ ] 是否有业务方说过、但产物里没出现的规则？（逐份对照上游故事与 UX）
- [ ] 权限类规则是否覆盖了所有角色？有没有"谁不能做"这类被漏掉的禁止项？
- [ ] 时序规则（先做什么、后做什么、什么不能同时）是否完整？漏掉前置/后置依赖了吗？

## 可判定性
- [ ] 每条 BR 是否能让开发**不问问题**直接实现？有没有"合理 / 适当 / 尽快 / 视情况"这类词？
- [ ] 边界值是否交代清楚？例如"≥500 触发"——499.99、500、500.01 各落入什么结果？
- [ ] 违反规则时系统的**拒绝行为**是否写明？（被拒后用户看到什么、数据变成什么）

## 一致性
- [ ] BR 之间是否自相矛盾（一条允许、另一条禁止同一场景）？
- [ ] BR 与上游已确认的状态机、字段校验、异常处理在语义上是否一致，无重复定义？

## 可追溯性
- [ ] 每条 BR 是否可追溯到一条来源（ST-XXX / FEA-XXX / 已确认决策）？
- [ ] AI 推断补充的规则是否明确标注 `AI_INFERENCE`，没有冒充 `FACT`？
- [ ] 有待确认的规则是否已进入父文档「待确认问题」并给出责任人？

## 最终判断
看完这份业务规则后，回答这两个问题：
1. **这些规则是否就是你真实的业务要求？** 有没有一条规则会让你对业务结果负责却写得不对？
2. **你可以直接拿这些规则去给开发/技术方实现吗？** 有哪些规则还需要补充说明？
