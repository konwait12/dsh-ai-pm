# 人类审查清单 · 系统校验（validation-rules）

> 本清单给 **PM/业务方** 在审查 AI 产出的 §系统校验（VL-XXX）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每条 VL 的取值口径（手机号段、金额上限、长度、码表）是否与业务方真实要求一致？有没有被 AI 猜过的值？
- [ ] 校验规则是否真的可执行？值域是否具体到"开发不问问题就能实现"？
- [ ] 跨字段约束（选 A 必填 B、A/B 互斥）是否与业务规则 `BR-XXX` 一致？

## 完整性
- [ ] 该功能下所有用户输入字段是否都被覆盖了校验？有没有漏掉必填项、上传文件、批量粘贴的数据？
- [ ] 有没有对只读/系统自动生成字段写了永远不会触发的校验？
- [ ] 必填/可选、格式、范围、长度、唯一性、跨字段各维度是否都覆盖到？

## 用户可读性
- [ ] 每条错误提示是否是中文、自然语言、可执行（说清哪里错 + 怎么改）？
- [ ] 是否区分「必填缺失 / 格式错误 / 超出范围 / 已存在冲突」，而不是统一一句"输入无效"？
- [ ] 错误提示是否有内部错误码、英文直译等开发向内容？

## 一致性
- [ ] VL 之间、VL 与 BR/字段定义之间是否自相矛盾？
- [ ] 是否存在"单查通过、联查就崩"的漏校验（跨字段依赖未定义）？
- [ ] 是否存在校验过严、把合法业务值拒之门外的"过度校验"？

## 可追溯性
- [ ] 每条 VL 是否可追溯到字段定义 / `BR-XXX` / 已确认决策？
- [ ] AI 推断的取值口径是否标注 `AI_INFERENCE`，没有冒充 `FACT`？
- [ ] 未定的校验边界是否已进入父文档「待确认问题」并给出责任人？

## 最终判断
看完这份系统校验后，回答这两个问题：
1. **这些校验是否就是你希望的数据门槛？** 有没有某条校验会让真实用户被拒而你不希望？
2. **你可以直接拿这些校验去给开发/测试实现吗？** 有哪些值域或文案还需要补充？
