# 人类审查清单 · 验收依据

> 本清单给 **PM/业务方/QA** 在审查 AI 产出的父文档 `function-description.md` §2 各 FUN 的「验收依据」小节时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每条 `AC-XXX` 的量化阈值是否与已确认的 `G-XXX` 目标一致？不是 AI 自定的数字？
- [ ] Given/When/Then 的触发条件与预期结果是否与上游 BR/VL/ST/EX 一致？（不会出现 VL 说姓必填、AC 却说姓可空）
- [ ] `then` 的结果是否可观测、可断言？没有写内部实现（调用接口、读写表）？

## 完整性
- [ ] 每个 P0 `FUN-XXX` 是否至少有一条主流程 AC + 一条异常/边界 AC？
- [ ] 涉及性能、容量、时间、金额等可量化结果时，是否都有具体阈值？没有「快速」「流畅」这类空话？
- [ ] 有没有明显「应该写但没写」的 AC？（关键业务路径、已确认的失败分支）

## 一致性
- [ ] 每条 AC 是否只判定一个行为（原子）？没有「并且」捆绑多个检查？
- [ ] 异常 AC 的失败结果是否与 `EX-XXX` 的恢复策略一致？（EX 说重试，AC 是否验证了重试后的结果？）
- [ ] `优先级` 是否与该 FUN 的 P0/P1 一致？没有 P0 全低优、P1 反而高优的错位？

## 可测性
- [ ] 如果我（QA）不看实现，按这条 AC 能否构造出通过和失败的验证输入？
- [ ] 每条 AC 的通过/失败判据是否唯一确定？不需要追问才能判定？
- [ ] 阈值是否有口径（平均值 / P95 / P99）和时间窗口？不是「响应快」这种无法测的表述？

## 可维护性
- [ ] AC 是对 BR/VL/ST/EX 的度量而非重写？没有重复定义规则？
- [ ] 有没有把测试用例/断言脚本/实现细节写进 AC？AC 是否保持为纯契约？

## 可追溯性
- [ ] 每条 `AC-XXX` 是否可追溯到所属 `FUN-XXX` 与目标 `G-XXX` / 来源文档？
- [ ] 推断补充的阈值是否标 `AI_INFERENCE`、未确认的标 `UNKNOWN` 并登记到待确认？

## 最终判断
看完这份验收依据产出后，回答这两个问题：
1. **你认同这些 AC 完整覆盖了本期的成功与失败标准吗？** 如果有缺失的验收点，缺什么？
2. **QA 拿到这张 AC 表能否直接开始构造用例验收？** 如果不能，哪些行还需要补充？
