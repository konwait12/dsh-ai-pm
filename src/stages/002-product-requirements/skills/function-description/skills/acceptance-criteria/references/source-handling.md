# Source Handling · 验收依据

## Source Register

为每个验收相关来源分配稳定 ID 并记录：

```text
source_id
title_or_description
format            # Stage 1 目标文档 / BRD / 业务规则 / 测试反馈 / 线上监控 / 会议纪要
author_or_speaker
provided_by
created_at
retrieved_at
authority_scope    # 能确认「阈值/目标」还是「现状观测」
location_or_link
notes
```

使用 `SRC-001`、`SRC-002` 递增编号。目标文档与业务决策能确认「阈值/完成定义」；测试反馈与线上监控只能确认「现状观测」，不构成业务目标。

## Extraction Rules

1. 先原样提取完成定义与阈值陈述，再归一化解释。
2. 对每条材料性阈值/成功标准保留来源位置与作者。
3. 区分「业务目标（应达到）」与「现状观测（当前值）」——现状是基线素材，目标是验收标准，不混写。
4. 排除的材料性内容（如"该标准不适用本期"）记录一句排除原因。
5. 永远不把"来源没提"当作"不需要阈值"；未确认的阈值标 `UNKNOWN`。

## Authority And Conflicts

评估来源权威性，不预设通用优先级：

1. 本项目明确的人工确认（目标决策人拍板阈值）；
2. 对该业务事实/完成定义的决策权（业务 owner 定成功标准，测试只能给可测性建议）；
3. 来源的直接程度（目标文档 vs 转述）；
4. 时效性及后声明是否显式取代先声明；
5. 独立来源相互印证。

当来源冲突（如 BR 说必填、AC 推断可空）：

- 保留双方陈述与来源 ID；
- 说明每种解读的影响；
- 识别可能的事实/决策 owner；
- 若改变材料性结论，标记 `conflict` 并停下，绝不静默选更方便的一方。

## Research Boundary

仅当外部事实能实质性改进验收判断且可查证时做研究（公开 SLA 标准、行业基准、竞品指标）。记录来源、日期、事实/推断状态、置信度、适用性与决策影响。

研究不能确认内部业务目标、可接受的性能/容量标准或验收范围。这些提交给有决策权的人。

## Mixed Media

- 目标文档 / BRD：提取可量化的 KPI 与基线（数值、百分比、时间窗口），标注目标归属。
- 测试反馈 / 缺陷记录：作为现状观测与验收可行性的佐证，不作为目标本身。
- 线上监控：记录指标口径（P95 还是平均值）、时间窗口、样本量。
- 会议纪要：区分「已拍板的目标/阈值」（DECISION）、「讨论中的标准」（ASSUMPTION/AI_INFERENCE）与「现状说明」（FACT 观察）。
