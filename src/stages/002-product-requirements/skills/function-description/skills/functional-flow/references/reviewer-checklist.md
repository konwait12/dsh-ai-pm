# 人类审查清单 · 功能流程（functional-flow）

> 本清单给 **PM/产品负责人/业务方** 在审查 AI 产出的 `function-description.md` §功能流程（主流程 / 分支流程 / 异常流程）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每个功能流程归属的 `FEA-XXX` 是否与功能清单一致？有没有凭空多出的流程？
- [ ] 分支条件是否与业务真实做法一致？（例如"名额满走排队"是业务真实的判定，还是 AI 猜的？）
- [ ] 起点是否覆盖了真实的所有触发方式？（用户主动、外部触发、后台代办、批量？）

## 完整性
- [ ] 每个 P0 功能是否都有主流程图？有没有 P0 功能没有画出主流程？
- [ ] 每个关键决策点是否都有分支流程？分支条件是否互斥、穷举？
- [ ] 每条关键路径是否有异常流程与回退目标？有没有"异常不可能发生"的乐观假设？

## 一致性
- [ ] 图内步骤名称与功能清单、上游故事名称是否一致？有没有图里叫"填写资料"、清单叫"信息登记"的错位？
- [ ] 异常流程与主流程是否自洽？主流程出现的分支是否都有对应的异常/回退说明？

## 可测性
- [ ] 每个分支条件是否明确到测试能写用例？（"如果时段已满"可以测；"如果合适"不可测）
- [ ] 如果我是接手开发的测试，只看流程能否列出每条路径的用例？

## 可维护性 / 可追溯性
- [ ] 每个步骤是否都能回溯到 `ST-XXX` 故事或 `FEA-XXX` 功能？AI 补的步骤是否标了 `AI_INFERENCE`？
- [ ] 有没有被 AI 静默丢弃的步骤/起点（上游故事里有、流程图里没有）？

## 最终判断
看完本功能流程章节后，回答：
1. **走完这些流程，业务结果能达成吗？** 如果不能，缺哪条路径或哪个步骤？
2. **你可以直接拿这些流程图去和开发开会吗？** 哪些分支或异常路径还需要你补充确认？
