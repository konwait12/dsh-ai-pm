# Thinking Framework · functional-flow

> **Common Core（必用）**：先应用 `src/framework/thinking-core.md` §1 的 6 个通用 lens（第一性原理 / 系统思考 / 对抗性审查 / 逆向验证 / 确认偏误防御 / 知识边界认知），再应用本文件领域透镜；Audit 前应用 `thinking-core.md` §2 校验层（事前验尸 / 空杯视角 / 可测试性 / 结论先行 / 读者视角）。只记录改变候选内容的发现，不重复粘贴分析。

目标：为每个已确认功能 `FEA-XXX` 生成起点 → 主流程步骤 → 分支流程 → 异常流程 → 出口的完整功能流程，穷举主 / 支 / 异常路径、确保流程完整，且不越界到布局、交互规则、业务规则或异常处理明细。

## 1. 起点透镜（Start Lens）

**问题**：此功能流程从哪个业务起点/触发条件启动？同一 FEA 是否存在多个起点，后续路径是否一致？

**反模式**：默认只画"从功能入口进入"的单一起点，忽略外部触发（推送、批量、定时、另一角色的代办）等真实起点，导致部分起点路径完全没有流程表达。

## 2. 主流程透镜（Main Path Lens）

**问题**：从起点到出口，业务依次执行哪些原子步骤？每个步骤的进入条件与离开条件是什么？

**反模式**：用一个大方框把"填写并提交"等复合动作压缩成一步，隐藏了中间必需的确认、校验、二次提交等步骤，下游无法据图挂接规则。

## 3. 分支透镜（Branch Lens）

**问题**：哪些决策点会产生分支？每个分支的条件表达式是否明确、互斥、可穷举？

**反模式**：画出的分叉没有条件标签（裸箭头），或条件存在重叠（同输入可同时落入两条路径）、遗漏（还有第三种情况未画出），图面"看起来全"实则不可执行。

## 4. 异常透镜（Exception Lens）

**问题**：主流程之外，失败/异常路径（错误、失败、超时、取消、恢复、数据为空）是否穷举？失败后回退到哪里？

**反模式**：只画"happy path"成功链路，把异常处理写成一句脚注甚至完全不画，异常回退目标悬空，评审时只能靠口头补全。

## 5. 交接透镜（Handoff Lens）

**问题**：流程是否跨越系统/模块边界或另一角色的触点？交接节点、输出数据、失败时的回退目标是否明确？

**反模式**：把跨系统交接画成一个与普通步骤无异的节点，不标注系统边界与失败回退路径，导致下游开发误以为交接总是成功、无需容错。

## Low-Density Degradation Mode

当输入只有一句话、没有任何流程材料（见 `SKILL.md` §1 Preflight 的 L1 判定）时，五个领域透镜无法产生有效工作。强行套用会产出冗长而空洞的流程。

```text
low-density input → skip 5-lens ideation
                   → do not enter Generate / Audit
                   → output only:
                      a) input sufficiency assessment（起点/步骤/分支/异常路径的缺失清单）
                      b) batched clarifying questions（每条：AI 初步判断 + 选项 + 影响 + owner）
                   → status = needs_user_input
                   → wait for human to fill in, then re-enter Preflight in sufficient mode
```

Degradation triggers（任一即触发）:

- 输入只有一句话且未提及任何流程起点、业务步骤
- 无 FEA 清单 / 无已确认故事，却要求"画个流程图"
- 用户只描述结果（"要能在线报名"）而没有任何路径信息

这不是失败状态，而是信息不足时的正确响应——省下人工评审时间，产出一批干净的澄清问题，而不是一张满是 `待确认` 的图。

## Confirmation Bias Defense（Wave-1 特化）

1. 我是不是只画了需求方口头描述的主流程，而没有独立质疑其分支与异常路径？
2. 需求方的"点击 X 就完成"是否隐藏了中间确认/校验步骤？我在图上有没有替他们补全却没标注？
3. 每个分支条件、异常路径是否来自上游功能清单/故事，还是我自己"合理推测"的？推测必须标 `AI_INFERENCE`。

## Knowledge Boundary（Wave-1 特化）

1. "故事里写了"（FACT）与"为了流程完整我补的"（AI_INFERENCE）是否可区分？
2. 异常路径、回退目标这些尚未确认的行为，是标 `UNKNOWN` 交人工，还是我擅自画定？
3. 跨系统交接的行为与失败处理是否归到了上游确认，而不是我在图里拍板？

停止于"结构化的功能流程模型"。布局（page-design）、交互规则（IX）、业务规则（BR/VL/AC）、状态机明细（STATE）与异常处理明细（EX）归下游子技能。
