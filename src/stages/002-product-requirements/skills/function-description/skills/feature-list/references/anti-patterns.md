# AI 常见反模式 · 功能清单（feature-list）

> 这些是 AI 在本子技能中最容易犯的错误。PM 审查时遇到以下模式应直接进入 Revision 修改确认。
>
> 注：本文示例统一使用通用业务场景（内容平台、企业服务、电商），避免与 `test/skills/` 下的测试夹具业务域（招聘网站、设备预测性维护、客户邀约活动等）同域，防止误导。

## AP1：把流程步骤当功能
- **表现**：把「导入 → 去重 → 校验 → 预览」拆成 4 个 FEA，或把主流程里的每一步都单独立项
- **为什么有害**：功能清单变成操作清单，粒度过碎，下游逐条实现成本高、可读性差
- **修复**：一个 FEA 对应一个内聚能力；流程步骤并入所属功能，不单独列功能

## AP2：功能无边界
- **表现**：写 "FEA-002: 客户管理" 只有名字，不写做什么、不做什么
- **为什么有害**：无边界的功能是黑盒，用户和下游都不知道它覆盖什么
- **修复**：每个 FEA 一句话描述写明 in/out，写不出边界就标 `UNKNOWN` 并提问

## AP3：无 ST 追溯、凭空造功能
- **表现**：写出一串 FEA-XXX，既不挂 ST-XXX，也没有任何来源
- **为什么有害**：下游无法追溯"凭什么"，功能变成无主声明，范围失控
- **修复**：每个 FEA 必须可追溯到 ≥1 个已确认 ST-XXX；孤儿功能删除或归位

## AP4：功能互相重叠
- **表现**：FEA-A "活动创建" 与 FEA-B "活动发布" 边界不清，用户分不清该用哪个
- **为什么有害**：一项操作能归属多个功能时，下游子技能会重复定义或冲突
- **修复**：边界表自检——任一动作只能归属一个功能；重叠则合并或重画

## AP5：把 UX / 交互 / 页面写进清单
- **表现**：功能清单里写 "点击提交后跳转成功页"、"按钮置灰"、页面布局
- **为什么有害**：UX 属于 product-ux；写进清单会让 WHAT 与 HOW 纠缠，下游无法复用
- **修复**：清单只写 WHAT；页面/交互/流程分别交 product-ux 与下游子技能

## AP6：全 P0 或优先级无理由
- **表现**：所有功能都标 P0，或只标字母不写理由
- **为什么有害**：全 P0 等于没有优先级，排期无依据；无理由的优先级无法被评审
- **修复**：用 MoSCoW（P0 = 缺它故事无法完成），每个功能写明优先级理由

## AP7：把推断当事实写进清单
- **表现**：AI 推断出"名单支持 CRM 同步"，未标 `AI_INFERENCE`，写进 FEA 的来源/描述
- **为什么有害**：业务方误以为"AI 已确认"，后续排期基于错误前提
- **修复**：推断边界标 `AI_INFERENCE` 并登记待确认；来源确认过的才标 FACT/DECISION

## AP8：范围缺口 / 越权静默处理
- **表现**：某故事找不到覆盖功能就跳过；某功能找不到来源故事就悄悄保留
- **为什么有害**：需求落空或范围越权都会导致交付偏差，且无人知晓
- **修复**：故事无功能 → 标缺口并提问；功能无故事 → 标越权并提问；都不静默处理
