# 人类审查清单 · 功能清单（feature-list）

> 本清单给 **PM/业务方** 在审查 AI 产出的 §功能清单（FEA-XXX）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每个 FEA 是否与你确认过的故事口径一致？有没有 AI 自己发明、你没提过的功能？
- [ ] 有没有你确认过的故事在清单里找不到对应功能（覆盖缺口）？
- [ ] 每个 FEA 所引用的 `ST-XXX` 是否确实存在，且确实是该功能的来源？

## 完整性
- [ ] 功能集合是否覆盖了范围基线的全部 in-scope 内容？out-scope 是否有明确排除？
- [ ] 客户/角色的每个关键动作是否有对应功能？有没有漏掉某类用户的入口？
- [ ] 每个功能是否写明"不做什么"（边界），而不是只有一个名字？

## 边界与重叠
- [ ] 有没有两个功能看起来是同一件事（如"活动创建"与"活动发布"）让人分不清该用哪个？
- [ ] 任一项用户操作能否明确归属到某一个 FEA？有没有一项操作能同时归到两个功能？
- [ ] 功能的粒度是否合适——既没有拆得太碎，也没有把两件事硬塞进一个功能？

## 优先级
- [ ] P0 的功能是否真的是"没有它某条故事就无法完成"？有没有把锦上添花也标成 P0？
- [ ] 每个功能的优先级是否有理由可讲，而不是随手标的？
- [ ] 若砍掉所有 P1/P2，故事是否仍能被 P0 功能完整支撑？

## 可追溯性
- [ ] 每个 FEA 是否可追溯到一个来源（ST-XXX / 已确认决策）？
- [ ] AI 推断补充的功能边界是否明确标注 `AI_INFERENCE`，没有冒充 `FACT`？
- [ ] 有待确认的功能边界是否已进入父文档「待确认问题」并给出责任人？

## 下游可消费性
- [ ] 拿着这份功能清单，`functional-flow` / `business-rules` 能否不回头翻故事就开始工作？
- [ ] 每个功能的一句话描述是否足以支撑后续分功能详述？

## 最终判断
看完这份功能清单后，回答这两个问题：
1. **这份清单就是你真实要做的功能范围吗？** 有没有多出来的、或者少掉的？
2. **你可以直接拿这份清单去给设计/开发排期吗？** 有哪些功能还需要补充边界说明？
