# 人类审查清单 · 页面设计（page-design）

> 本清单给 **PM/产品负责人/业务方** 在审查 AI 产出的 `product-ux.md` §2（页面设计）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 页面清单是否与 `functional-flow` 功能流程步骤一一对应？有没有 AI 凭空加出的页面？
- [ ] 每页的入口与前置条件是否真实？例如"场地详情页"的前置条件"场地存在且可预约"是业务真实的吗？
- [ ] 每个操作的下一状态是否指向真实存在的页面？有没有指向不存在页面的悬空链接？

## 完整性
- [ ] 流程中的每个步骤是否都有对应页面行？有没有漏掉的步骤？
- [ ] 关键页面（列表、表单、结果）的空态、失败态、加载态是否都有对应的处理/去向？
- [ ] 每个页面是否至少有一个用户可执行的操作？有没有"只能看不能点"的死页面？

## 一致性
- [ ] 页面名称与 `functional-flow` 功能流程步骤名、上游故事中的叫法是否一致？
- [ ] 前置条件之间有没有矛盾？（例如"已登录"与"允许游客浏览"同时成立）
- [ ] §2.1 页面清单与 §2.2 分支流程（function-description 功能流程）的分支去向是否自洽？

## 可测性
- [ ] 每个操作的"下一状态"是否明确到测试能写用例？（"跳转结果页"可以测；"刷新状态"不可测）
- [ ] 如果我是接手实现的开发，只看这一行能否知道页面上要放什么、点了去哪？

## 可维护性 / 可追溯性
- [ ] 每个页面是否都能回溯到 `FEA-XXX` 和 `ST-XXX`？AI 补的页面/字段是否标了 `AI_INFERENCE`？
- [ ] 有没有被 AI 静默丢弃的流程步骤（上游有、§2 没有）？

## 最终判断
看完 §2 后，回答：
1. **用户按这张页面清单走完流程，能达成目标吗？** 如果不能，缺哪个页面或哪个操作？
2. **你可以直接拿这份页面清单去和开发/设计对需求吗？** 哪些入口、前置条件或下一状态还需要你确认？
