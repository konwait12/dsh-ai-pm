# Question Patterns · page-design

八种 Clarify 提问模板（一次一问的澄清循环）。每条给出：**何时用 / 问句骨架 / 三个示例 / 常见陷阱**。

---

## 1. 页面归属（Page Ownership）

**何时用**：某页面不知道该归哪个 FEA，或疑似属于相邻功能的页面。

**问句骨架**：
```
[为什么重要] 页面归属不清会造成与相邻功能重复或遗漏。
当前 [页面] 疑似跨越 [FEA-A] 与 [FEA-B]。请确认: 主归属是哪个? 边界在哪?
```

**示例**：
- ""历史订单列表"该属于订单查询还是订单管理？是同一个功能吗？"
- "这个确认弹窗是否属于主流程页面？还是支付功能自己的？"
- "空态引导页是归属功能页面，还是全局通用页？"

**常见陷阱**：把相邻功能页面画进来；或该画没画；归属由 AI 拍板而非确认。

---

## 2. 入口与前置（Entry & Precondition）

**何时用**：页面入口不完整，或前置条件列空缺、不明确。

**问句骨架**：
```
[为什么重要] 入口与前置缺失会导致页面"不知道何时被看到"。
当前 [页面] 入口写了 [已有入口]。请确认: 外部直达入口（深链/推送/分享）存在吗? 进入前必须满足什么条件?
```

**示例**：
- "场地详情页只能从列表进入吗？分享链接能否直达详情？"
- "进入填写页前是否必须已登录？未登录用户会被引导到哪？"
- "前置条件'场地可预约'的数据由谁保证？状态过期了怎么办？"

**常见陷阱**：只写站内入口；前置条件写"已登录"等宽泛条件；漏掉权限/数据前置。

---

## 3. 页面内容（Content）

**何时用**：主要内容列空缺，或写成了视觉/布局描述。

**问句骨架**：
```
[为什么重要] 内容不清则开发不知道页面上放什么。
当前 [页面] 主要内容写了 [已有内容]。请确认: 本页呈现哪些信息区块 / 列表 / 表单字段?
```

**示例**：
- "场地列表页除了卡片，是否还要筛选条、排序、地图视图入口？"
- "详情页需要哪些字段？（价格、可订时段、设施、评价、交通）哪些是必展示？"
- "填写页包含哪些字段？身份证号这类敏感字段本期要吗？"

**常见陷阱**：用"顶部放个大按钮"代替信息描述；把交互微细节写进内容；堆砌视觉词。

---

## 4. 操作集合（Action Set）

**何时用**：页面操作不全，或操作与下一状态不对应。

**问句骨架**：
```
[为什么重要] 操作缺失/悬空会导致页面不可用。
当前 [页面] 操作有 [已有操作]。请确认: 用户在页面上还能做什么? 每个操作的下一状态是什么?
```

**示例**：
- "列表页除了查看详情，用户能否收藏、比较、筛选？这些是本期范围吗？"
- "表单页的'提交'和'保存草稿'是否都要？各自去向哪里？"
- "结果页除返回列表外，是否要'再次预约''分享给朋友'？"

**常见陷阱**：操作列了没下一状态；把多个操作合并一句；操作超出范围（范围蔓延）。

---

## 5. 下一状态（Next State）

**何时用**：操作后的去向不明确，或存在悬空箭头。

**问句骨架**：
```
[为什么重要] 下一状态悬空会导致流程断链。
当前 [操作] 的下一状态未写明。请确认: 成功后去哪? 失败后去哪? 停留在本页还是退出流程?
```

**示例**：
- ""提交"成功后是跳结果页，还是停留表单并显示成功提示？"
- "保存草稿成功后是留在本页，还是返回列表？"
- "支付失败是停留收银页重试，还是退回订单详情？"

**常见陷阱**：只写成功路径；"更新状态"类含糊去向；把失败去向交给下游猜。

---

## 6. 状态覆盖（State Coverage）

**何时用**：只设计主路径页面，空/加载/失败/超时/权限不符等状态页缺失。

**问句骨架**：
```
[为什么重要] 状态页缺失则测试与下游无法覆盖异常。
当前只有 [主路径]。请确认: 空数据 / 加载中 / 无权限 / 数据过期 各显示什么、通向哪?
```

**示例**：
- "场地列表为空时显示什么？'暂无可用场地'下面要不要给重新筛选的入口？"
- "加载中状态是骨架屏还是 loading 转圈？这会由原型/前端定，还是需要确认？"
- "进入已下线的场地详情，显示什么？404 页还是提示'该场地已下线'？"

**常见陷阱**：只画主路径；状态页缺失；把状态处理当作"开发的事"。

---

## 7. 页面拆分依据（Page Split）

**何时用**：同一功能页面数量多，或疑似按"屏幕数"机械拆分。

**问句骨架**：
```
[为什么重要] 拆分无依据会造成页面冗余或过粗。
当前 [功能] 拆成 [N] 页。请确认: 拆分的依据是步骤/状态差异，还是屏幕数?
```

**示例**：
- ""填写信息"拆成两页（基本信息和详细信息），依据是什么？可以合并吗？"
- "确认页和结果页是否可以合成一页？还是必须分开展示？"
- "弹窗内容是否应独立成页？还是作为详情页的一部分？"

**常见陷阱**：按"屏幕数"切页；合并了本应分开的状态页；拆分理由无据。

---

## 8. 原型需求（Prototype Need）

**何时用**：不确定是否需要生成可点击 HTML 原型。

**问句骨架**：
```
[为什么重要] 原型是沟通载体，不是必须交付物。
当前流程有 [页数] 页。请确认: 需要生成可点击原型给多方评审吗? 还是文本表格够用?
```

**示例**：
- "场地预约流程 5 页，需要原型给业务方评审吗？还是先文本确认？"
- "多角色（用户/运营）都要看，是否生成原型作为演示？"
- "原型只做 P0 主路径，还是包含全部状态分支？"

**常见陷阱**：默认要原型；或从不做原型；原型范围与文本不一致。

---

## 通用建议

1. **一次只问一个**，按 Impact × Uncertainty 排序，先问阻断入口/前置/下一状态的。
2. **不要问 AI 能查的事实**（平台规范、常见页面惯例）——自己查。
3. **每问必带 AI 初步判断**，让产品从选项里选而不是从零想。
4. **给 2-4 个互斥选项 +「其他」兜底**。
5. **回写位置必填**：每答一题必须能指向 §2.1 的具体行或列。
