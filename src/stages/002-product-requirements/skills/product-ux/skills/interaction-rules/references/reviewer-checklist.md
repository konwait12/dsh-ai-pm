# 人类审查清单 · 交互规则（interaction-rules）

> 本清单给 **PM/产品负责人/业务方** 在审查 AI 产出的 `product-ux.md` §3（交互规则 IX-XXX）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 每条规则的"触发条件 → 系统响应"是否与业务真实行为一致？"提交成功跳结果页"是真的吗？
- [ ] 错误提示文案/超时行为是否与业务方实际希望的一致？还是 AI 编的？
- [ ] 每条规则引用的页面是否在 §2 页面设计清单中存在？有没有孤儿规则？

## 完整性
- [ ] 关键页面的每个可交互元素（按钮、输入框、列表项、Tab、链接）是否都有对应规则？
- [ ] 每条规则的 loading / 空态 / 失败 / 禁用 / 超时状态是否都有去向？
- [ ] 弹窗的打开、关闭、遮罩点击、取消、确认后动作是否都定义了？

## 一致性
- [ ] 规则中的"下一状态"与 §2 页面设计表的"下一状态"是否一致？有没有两边说法不同？
- [ ] 规则与 `functional-flow` 功能流程分支条件是否对应？（例如流程里"名额满走另一分支"，规则里是否写了置灰）
- [ ] 同类交互在不同页面是否有相同/相异的明确理由？还是随意复制？

## 可测性
- [ ] 每条规则是否明确到测试能写用例？（"点击后跳转结果页"可以测；"提交后合理提示"不可测）
- [ ] 如果我是接手实现的开发，只看这一条能否实现？响应是具体动作还是模糊形容词？

## 边界正确性
- [ ] 有没有数据校验（"密码必须 8 位"）、计算（"合计金额"）、权限（"仅管理员可"）被错误写进交互规则？
- [ ] 这类内容是否已标注应归 function-description，而不是留在 §3？

## 可追溯性
- [ ] 每条规则是否可回溯到 `FEA-XXX` 与 `PG-XXX`？AI 补的规则是否标了 `AI_INFERENCE`？
- [ ] 有没有被 AI 静默丢弃的页面交互（页面有操作、规则表没有）？

## 最终判断
看完 §3 后，回答：
1. **用户按这些规则操作，每一步的反馈是否符合你的预期？** 哪些反馈是你希望改的？
2. **你可以直接拿这些规则去和开发对交互吗？** 哪些触发、响应或异常处理还需要你补充确认？
