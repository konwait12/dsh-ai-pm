# Question Patterns · interaction-rules

八种 Clarify 提问模板（一次一问的澄清循环）。每条给出：**何时用 / 问句骨架 / 三个示例 / 常见陷阱**。

---

## 1. 触发条件（Trigger）

**何时用**：规则的触发条件不清，或无法确定用户在什么状态下执行什么操作。

**问句骨架**：
```
[为什么重要] 触发不清则规则不可实现、不可测试。
当前 [元素] 触发写了 [已有条件]。请确认: 用户在什么状态/位置执行什么操作会触发?
```

**示例**：
- "提交按钮在表单未填完时是否可点？还是必须全部填完才点亮？"
- "下拉刷新的触发是手势还是按钮？列表为空时还能下拉吗？"
- "分享入口在详情页一直显示，还是滚动到特定区域才出现？"

**常见陷阱**：把"用户状态"漏掉；触发与页面入口矛盾；把业务判定条件当成触发。

---

## 2. 系统响应（Response）

**何时用**：只写了功能句没有系统响应，或响应含糊（"合理提示"）。

**问句骨架**：
```
[为什么重要] 响应必须具体到可观察，否则开发靠猜。
当前 [操作] 的响应写了 [已有内容]。请确认: 系统具体做什么? 跳转/弹窗/toast/状态变化/文案是什么?
```

**示例**：
- "点击'保存'后，系统是跳结果页，还是停留并显示 toast？文案是什么？"
- "'加载失败'的提示具体显示在哪？重试按钮是重新请求还是整页刷新？"
- "删除后是立即移除列表项，还是先弹确认再移除？"

**常见陷阱**：用"合理提示""适当反馈"糊弄；只写系统动作不写界面变化；文案不落定。

---

## 3. 状态覆盖（State Coverage）

**何时用**：规则只有成功路径，loading/empty/error/disabled/timeout 缺失。

**问句骨架**：
```
[为什么重要] 状态缺失则测试无法覆盖异常。
当前 [元素] 只有 [成功态]。请确认: 加载中/空数据/失败/禁用/超时 分别显示什么、如何恢复?
```

**示例**：
- "提交按钮点击后立即进入 loading 吗？loading 文案是'提交中'吗？"
- "接口超时（如 5s）后用户看到什么？自动重试还是手动重试？"
- "列表为空时'加载更多'按钮显示什么状态？置灰还是隐藏？"

**常见陷阱**：只写成功路径；把状态处理当"开发的事"；超时/断网反馈缺失。

---

## 4. 边界门（Boundary）

**何时用**：疑似把数据校验、计算、权限写进了交互规则。

**问句骨架**：
```
[为什么重要] 边界污染会让下游无法分工。
当前规则含 [内容]。请确认: 这是页面层交互，还是业务判定? 后者应归 function-description。
```

**示例**：
- ""密码必须 8 位以上"是交互规则还是校验规则？错误提示由哪层定义？"
- ""仅 VIP 可见预约入口"是权限规则吗？应由谁判定可见性？"
- ""库存不足禁止下单"是业务规则，但'按钮置灰的呈现'是交互规则——两者如何分工？"

**常见陷阱**：把 VL/BR/权限揉进 IX；看到关键词不移交；错误提示归属不清。

---

## 5. 反馈时机（Feedback Timing）

**何时用**：反馈的时机/频率不清（立即 vs 异步、每次 vs 一次性）。

**问句骨架**：
```
[为什么重要] 反馈时机影响用户体验与实现复杂度。
当前 [反馈] 的时机未写明。请确认: 是即时反馈还是异步结果? 输入时逐字校验还是失焦校验?
```

**示例**：
- "表单校验是输入时实时提示，还是点击提交后统一提示？"
- "进度提示是立即显示，还是等待接口返回后才显示？"
- "上传进度是分片百分比，还是仅'上传中'字样？"

**常见陷阱**：反馈时机模糊；把异步回调当即时结果；实时校验与提交校验混写。

---

## 6. 异常与边界行为（Exception & Edge）

**何时用**：异常处理、重复操作、网络异常、前后台切换等边界未定义。

**问句骨架**：
```
[为什么重要] 边界行为不定义，线上会以最坏方式暴露。
当前 [规则] 无异常/边界说明。请确认: 重复点击/断网/前后台切换/多端登录 如何处理?
```

**示例**：
- "快速连点'提交'，是否防抖只处理第一次？"
- "提交中途断网，数据保留吗？下次进入是恢复还是重填？"
- "App 切后台再回来，弹窗还开着吗？输入内容还在吗？"

**常见陷阱**：只写主路径；边界行为靠"常识"；重复操作/多端登录未处理。

---

## 7. 复用与覆盖（Reuse & Coverage）

**何时用**：多条页面有相似交互，或疑似有孤儿/漏写规则。

**问句骨架**：
```
[为什么重要] 复用不清会导致规则重复或覆盖不全。
当前 [交互] 出现在 [多个页面]。请确认: 是共用一条规则，还是各自不同? 有没有页面漏了规则?
```

**示例**：
- ""保存"操作在列表页、详情页都有，行为完全一致吗？能否共用一条 IX？"
- "所有列表页的空态是否统一？还是各页不同？"
- "支付失败提示在哪些页面出现？是否有页面遗漏了失败规则？"

**常见陷阱**：无依据地复制规则；或共用规则掩盖真实差异；孤儿/漏写未被发现。

---

## 8. 可访问性（Accessibility）

**何时用**：涉及键盘、读屏、焦点、触屏目标尺寸等 a11y 行为，或产品有明确无障碍要求。

**问句骨架**：
```
[为什么重要] a11y 行为缺失会排除部分用户。
当前 [元素] 无 a11y 规则。请确认: 键盘可达吗? 读屏有标签吗? 触屏目标够大吗?
```

**示例**：
- "弹窗关闭是否支持 Esc 键？焦点是否回到触发按钮？"
- "图片搜索入口有 ARIA 标签吗？读屏用户如何描述？"
- "触屏按钮的最小点击区域是多少？（推荐 ≥44px）"

**常见陷阱**：默认不做 a11y；引标准不落行为；把 a11y 当"前端的事"。

---

## 通用建议

1. **一次只问一个**，按 Impact × Uncertainty 排序，先问阻断触发/响应的。
2. **不要问 AI 能查的事实**（平台规范、WCAG/ARIA 标准、常见交互惯例）——自己查。
3. **每问必带 AI 初步判断**，让产品从选项里选而不是从零想。
4. **给 2-4 个互斥选项 +「其他」兜底**。
5. **回写位置必填**：每答一题必须能指向 §3 交互规则的具体规则 ID 或新增规则。
