# 交互规则写作规范（Rule Writing Format）

> 本文件定义交互规则的标准书写格式，适用于所有 IX-XXX 规则产出。
> 定位：本文件定义 IX-XXX 规则的**表达格式**与质量基线；边界判定（页面层 vs 业务层）仍以 `SKILL.md` 与 `thinking-framework.md` 为准。

## 1. 核心原则

> **IR 呈现 BR 的结果，BR 定义 IR 的依据，埋点记录两者的全过程。**

- 交互规则（IX）描述「用户做什么 → 系统怎么反馈 → 异常怎么提示 → 边界怎么处理」，站在**用户视角**。
- 业务规则（BR/VL，属于 function-description）描述「输入什么 → 怎么判断 → 输出什么 → 错了怎么办」，站在**系统视角**。
- 两者必须分离：IX 只写页面层；一旦命中数据校验 / 计算 / 权限 / 状态机判定，移交给 function-description。

## 2. 段落式格式（默认，不用表格）

每条 IX 用**段落式**表达，不用表格分列（表格视觉疲劳、列间关系松散）：

```markdown
**I{编号}：{交互名称}**
- [用户状态] + [用户动作]，将会[系统响应]
- IF [条件]，[用户动作]，[系统响应]
- ELSE [条件]，[用户动作]，[系统响应]

**异常**：
- [异常情况]，[用户动作]，[系统反馈]，[提示文案]

**边界**：
- [边界情况]，[处理方式]
```

### 正确示例

```markdown
**IX-001：内容封面图上传**
- 已登录用户点击封面图上传按钮，将会打开文件选择器，选择图片后进入裁剪预览页面
- 未登录用户点击封面图上传按钮，将会跳转到登录页面，登录完成后回到上传入口

**异常**：
- 用户上传图片格式不支持，将会显示「仅支持 JPG/PNG/WEBP」提示，停留在上传入口
- 系统异常时，显示「上传失败，请重试」提示，提供重试选项

**边界**：
- 快速重复点击上传按钮，仅处理第一次点击（防抖）
```

### 错误示例（需避免）

```markdown
❌ 使用表格分列（视觉疲劳、关系松散）
| 条件 | 操作 | 结果 |
|------|------|------|

❌ 结构不一致（有的写触发、有的写响应）
- I01：用户点击 → 系统响应
- I02：系统判断 → 用户看到

❌ 缺少用户状态（未说明触发时用户处于什么状态）
- 用户点击按钮，系统响应
```

## 3. 强制要素（每条 IX 必须覆盖）

1. **规则 ID**：全局唯一，`IX-001` 递增，与 `page-design` 页面、`functional-flow` 功能流程步骤关联。
2. **用户状态**：描述触发时的用户状态（已登录 / 未登录 / 已注册 / 特定角色）。
3. **用户操作**：具体动作（点击、长按、滑动、输入）。
4. **系统反馈**：操作后的确定响应（页面跳转、弹窗、toast、状态变化）。
5. **异常提示**：异常情况的处理与提示文案（至少覆盖 BR 中定义的关键错误）。
6. **边界处理**：至少考虑——快速重复操作（防抖）、网络异常、前后台切换、多端登录。

## 4. 状态覆盖（每页至少覆盖）

- 加载状态（loading）
- 空状态（empty）
- 错误状态（error）
- 禁用状态（disabled，如权限不足、feature flag 关闭）
- 超时与重试

## 5. 评审 Checklist

- [ ] 每条交互有唯一编号，关联到具体页面/功能（FEA-XXX）
- [ ] 正常流程步骤清晰，用户动作与系统反馈一一对应
- [ ] 异常流程覆盖业务规则中定义的所有错误码
- [ ] 边界情况至少考虑：快速重复操作、网络异常、前后台切换、多端登录
- [ ] 加载状态、空状态、错误状态有明确设计
- [ ] 段落式表达，无表格分列
- [ ] 无领域层内容泄漏（命中校验/计算/权限 → 移交 function-description）
- [ ] 每条例句可直接实现、可直接测试（无「合理提示」「适当反馈」类模糊词）

## 6. 与 function-description 的关联示例

同一场景下，IX 写页面层、BR 写领域层，二者通过 ID 关联：

```markdown
### Interaction Rules（本子 Skill）
**IX-002：点击图片搜索图标**
- 认证用户点击图片搜索图标，将会触发图片识别搜索
- IF agreementAccepted=true，跳过协议卡片，直接进入相机预览
- ELSE 显示协议卡片
- IF image-search=关闭，无反应或显示「功能维护中」
```

```markdown
### Business Rules（function-description，非本子 Skill）
**BR-001：入口可见性规则**
- 输入：用户身份（来自 session）
- 判断：用户是否为认证用户 → 是则显示图片搜索图标，否则隐藏
- 输出：成功 = 显示图片搜索图标；失败 = 隐藏图片搜索图标；异常 = N/A
```

> 关联规则：IX 描述「用户看到/操作什么」，BR 描述「系统如何判定」。IX 引用 BR 的输出结果（如 IX-002 依赖 BR-001、BR-002 的输出）。
