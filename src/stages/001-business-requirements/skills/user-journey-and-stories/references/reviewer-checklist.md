# 人类审查清单 · 用户旅程与用户故事

> PM/业务方审查 `user-journey-and-stories` 产物时使用。

## 正确性
- [ ] §1 生命周期阶段划分是否符合业务的真实流程？（不该合并的有没有被合并？不该拆的有没有被拆？）
- [ ] §2 旅程图中每个角色的行为描述是否符合实际？痛点和来源能否对上上游 §4？

## 完整性
- [ ] 上游 confirmed 背景中的**全部角色**都出现在旅程图中了吗？有没有遗漏的角色？
- [ ] §5 路径类型覆盖：正常/备选/异常/失败/交接/恢复——是否有明显的遗漏？（例如：用户投递失败后怎么办？候选人状态从"面试"到"录用"中间的交接路径？）
- [ ] §3 故事卡片：每个 P0 旅程条目是否都有对应的 ST-XXX？

## 一致性
- [ ] §3 故事卡片中的角色名、场景描述是否与 §2 旅程图中的一致？
- [ ] 同一个角色在不同生命周期阶段的行为是否前后连贯？

## 可测性
- [ ] 故事卡片格式是否正确？`在〈场景〉下，作为〈角色〉，我希望〈动作〉，以便〈目标〉`——每条是否完整？
- [ ] ST 的"目标/价值"部分是否写的是业务结果而非功能？

## 可维护性
- [ ] §4 覆盖矩阵：有缺口的条目是否都标注了原因？
- [ ] §9 来源追溯：每个旅程条目是否都能追溯到上游的 SRC-* 或 FACT？

## 最终判断
1. 按这个旅程图走一遍，有没有哪个角色在某个阶段的体验让你觉得"不对，实际不是这样的"？
2. 按这些故事卡片开始开发，开发团队能不能理解"为谁、在什么场景、做什么、为什么"？
