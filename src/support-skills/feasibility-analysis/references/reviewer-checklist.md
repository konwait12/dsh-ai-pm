# 人类审查清单 · 可行性分析

> 本清单给 **PM/决策人** 在审查 AI 产出的 `feasibility-report.md`（含 §多方案取舍 章节，结构参考 `solution-comparison.md`）时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 成本/风险/周期数据是否真实或有明确来源？AI 估算是否标了 `AI_INFERENCE`/`ASSUMPTION`？
- [ ] 每个方案的技术依赖、范围影响、时间影响描述是否与实际一致？
- [ ] 可行性结论（做/不做/有条件做）是否对应了上面四维度的证据？

## 完整性
- [ ] 是否所有真正不同的候选方案都被纳入？有没有被遗漏的第三个方案（如"外购+定制"混合方案）？
- [ ] §多方案取舍 章节中，每个方案的描述深度是否一致？（有没有一个明显更详细 = AI 悄悄站队）
- [ ] 敏感度分析是否写明了"哪个权重 ±1 会翻转结论"？

## 一致性
- [ ] 权重是否在打分**之前**定义？（如果权重的设定像是为了某个方案赢，需要质疑）
- [ ] AI 推荐是否真的由矩阵算出来，还是 AI 先定了结论再挑数字？
- [ ] 如果推荐方案改变了范围，是否点名了需要回流的 Work Item？

## 可测性
- [ ] "有条件做"的条件是否具体可衡量（什么条件、由谁、何时验证）？
- [ ] AI 推荐是否带置信度（高/中/低）和"什么假设成立时才成立"？

## 可维护性
- [ ] 来源追溯是否覆盖全部成本/风险数据？无来源的"事实"是否存在？
- [ ] 决策是否已登记 `DEC-XXX`（含决策人、理由、日期）？

## 可追溯性
- [ ] 结论能否被下游直接使用（选中方案 + 范围影响 + 假设清单）？
- [ ] 若有回流，最早受影响的 Work Item 是否明确？

## 最终判断
看完这份产物后，回答这两个问题：
1. **你认同这份评估和 AI 推荐吗？** 如果认同，基于产物的哪些证据？如果不认同，缺什么？
2. **你能据此拍板吗？** 如果可以，最终选哪个方案/做还是不做？如果不可以，缺什么信息、需要问谁？
