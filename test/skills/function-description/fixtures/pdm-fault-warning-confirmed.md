## 2. 功能流程

> 把功能清单组织为主流程 / 分支流程 / 异常流程。每个流程步骤引用 FEA-XXX。

### 2.1 主流程（P0）

> 故障预警引擎（FUN-003）闭环主流程。

```text
1. 数据采集层持续推送设备运行参数（温度/振动/压力/电流）到预警引擎（FEA-001 / FUN-001）
2. 引擎按基线模型比对当前参数
3. 检测到偏离 → 计算偏离程度和趋势 → 判定故障概率和预计发生时间
4. 故障概率 ≥ 阈值 → 触发预警（BR-001）
5. 推送预警通知给维修技师和设备主管
6. 技师查看预警详情（异常参数/趋势图/建议操作/所需备件）
7. 主管评估后决定：生成工单 或 标记误报
```

### 2.2 分支流程

| 决策点 | 判定条件 | 去向 | 条件是否互斥/穷举 |
|---|---|---|---|
| 预警评估 | 严重度 CRITICAL（故障概率 ≥ 90%） | 升级路径：通知工厂厂长、协调生产计划（BR-002） | 是 |
| 预警评估 | 严重度 HIGH（70% ≤ 故障概率 < 90%） | 正常路径：生成工单 或 标记误报 | 是 |
| 误报判定 | IT 确认误报 | 记录进入训练负样本，反馈模型 | 是 |

### 2.3 异常流程

| 异常场景 | 触发条件 | 流程走向 | 回退目标 |
|---|---|---|---|
| 传感器数据中断 | 连续缺失 > 60s | 标记设备"数据中断"，暂停该设备预警 | 恢复后自动重新接入 |
| 预警引擎宕机 | 引擎进程无响应 > 30s | 自动重启引擎，重启期间使用缓存基线 | 重启后回放中断期间数据 |
| 基线模型退化 | 误报率连续 7 天 > 30% | 自动标记"基线需调整"，通知 IT | IT 手动或供应商提供新基线 |
